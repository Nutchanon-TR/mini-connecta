# Mini Connecta Release 1 Product Backlog

อ้างอิง Connecta Release 1 Product Backlog ฉบับ 16 พฤศจิกายน 2569 และปรับตาม [แผน Mini Connecta](plan.md)

**เป้าหมาย** ผู้ทดสอบเปิด Mini Connecta ผ่าน HTTPS เข้าด้วยบัญชี Google ตั้งชื่อและเลือกตัวละคร เปิด Discover แล้วเข้า Study Room ห้องเดียวกันจากคนละเครื่อง เพื่อเดินพบและคุยกันตามระยะ

## R1-01 เข้าสู่ระบบและออกจากระบบ

ในฐานะผู้ทดสอบ ฉันต้องการเข้าด้วยบัญชี Google เพื่อกลับมาใช้บัญชีเดิมและเข้าห้องได้ตามสิทธิ์

**งานย่อย**

- [ ] `R1-01.1` ตั้งค่า Google OAuth และ URL สำหรับกลับเข้า Mini Connecta บนเครื่องพัฒนาและระบบทดสอบ
- [ ] `R1-01.2` ทำหน้าเข้าสู่ระบบและปุ่ม Continue with Google
- [ ] `R1-01.3` รับผลจาก Google และสร้างบัญชีใหม่หรือเรียกบัญชีเดิมด้วยรหัสตัวตนจาก Google
- [ ] `R1-01.4` ออก Session หลังยืนยันตัวตนและอ่าน Session เมื่อเปิดหน้าหรือรีเฟรช
- [ ] `R1-01.5` ทำปุ่มออกจากระบบและยกเลิก Session เดิม
- [ ] `R1-01.6` แสดงข้อความเมื่อผู้ใช้ยกเลิก เข้าสู่ระบบไม่สำเร็จ หรือ Session หมดอายุ พร้อมให้เริ่มใหม่

**เกณฑ์ตรวจรับ**

- เข้าสู่ระบบด้วย Google สำเร็จแล้วระบบสร้างบัญชีครั้งแรก และการเข้าครั้งถัดไปด้วยบัญชี Google เดิมเปิดบัญชีเดิมของ Mini Connecta
- รีเฟรชหน้าแล้วคงสถานะเข้าสู่ระบบไว้ตราบใดที่ Session ยังใช้ได้ เมื่อหมดอายุให้กลับไปเข้าสู่ระบบ
- ผู้ที่ยกเลิกหรือเข้าสู่ระบบไม่สำเร็จเห็นข้อความและเริ่มใหม่ได้
- ออกจากระบบแล้ว Session ใช้งานต่อไม่ได้ และการเปิด Discover อีกครั้งต้องเข้าสู่ระบบใหม่

## R1-02 ตั้งชื่อและเลือกตัวละคร

ในฐานะผู้ใช้ใหม่ ฉันต้องการตั้งชื่อและเลือกรูปลักษณ์ตัวละคร เพื่อให้เพื่อนจำฉันได้เมื่อเข้าห้อง

**งานย่อย**

- [ ] `R1-02.1` ทำช่องชื่อแสดงผลและตรวจความยาวไม่เกิน 16 ตัวอักษรทั้งฝั่ง UI และ API
- [ ] `R1-02.2` เตรียม preset และแสดงตัวอย่างก่อนบันทึก
- [ ] `R1-02.3` บันทึกตัวละครหนึ่งตัวต่อบัญชีและใช้ค่าที่บันทึกเมื่อเข้าห้อง
- [ ] `R1-02.4` แจ้งจุดที่ต้องแก้เมื่อข้อมูลไม่ผ่านหรือบันทึกไม่ได้ และให้ลองใหม่
- [ ] `R1-02.5` กำหนดให้ผู้ใช้ใหม่สร้างตัวละครก่อน Join และให้ผู้ใช้เดิมข้ามขั้นนี้

**เกณฑ์ตรวจรับ**

- ผู้ใช้ใหม่บันทึกชื่อแสดงผลและ preset ได้ ก่อนเข้าห้อง
- ส่งค่าที่ไม่ผ่านหรือเซฟล้มเหลวแล้วผู้ใช้เห็นวิธีแก้และลองใหม่ได้ การส่งซ้ำยังมีตัวละครหนึ่งตัวต่อบัญชี
- เปิดเว็บหรือเข้าสู่ระบบด้วยบัญชีเดิมแล้วเห็นตัวละครที่บันทึกไว้และไป Discover ได้ทันที

## R1-03 เปิดห้องทดสอบ Cosy Library

ในฐานะผู้ทดสอบ ฉันต้องการเข้าฉากห้องสมุด 3 มิติ เพื่อมีพื้นที่เดินพบและพูดคุยกับเพื่อน

**งานย่อย**

- [ ] `R1-03.1` นำฉาก Cosy Library ที่มีอยู่มาเปิดบนหน้าห้องทดสอบ
- [ ] `R1-03.2` กำหนดจุดเกิดและตรวจว่าผู้เล่นเดินออกจากจุดเกิดได้
- [ ] `R1-03.3` ใช้ข้อมูลขอบแผนที่และสิ่งกีดขวางชุดเดียวกันกับฝั่งเซิร์ฟเวอร์
- [ ] `R1-03.4` วางกล้องและตัวละครให้เห็นทางเดินและเฟอร์นิเจอร์ชัดเมื่อเข้าฉาก
- [ ] `R1-03.5` แสดงสถานะโหลดฉาก พร้อมปุ่มลองใหม่เมื่อโหลดไม่สำเร็จ

**เกณฑ์ตรวจรับ**

- ฉาก Cosy Library โหลดบนเบราว์เซอร์และแสดงพื้น ทางเดิน เฟอร์นิเจอร์ และจุดเกิดที่ตัวละครเดินออกได้
- ผู้ใช้เห็นสถานะระหว่างโหลด หากโหลดฉากไม่สำเร็จ ระบบแสดงวิธีลองใหม่
- ผู้เล่นทุกคนในห้องเดียวกันเห็นแผนที่และขอบเขตสิ่งกีดขวางชุดเดียวกัน

## R1-04 เข้าห้อง Study Room ผ่าน Discover

ในฐานะผู้ทดสอบ ฉันต้องการเปิด Discover แล้ว Join Study Room เพื่อเข้าไปพบเพื่อนในห้องเดียวกัน

**งานย่อย**

- [ ] `R1-04.1` ทำแถบนำทางให้มี Discover เป็นเมนูเดียว
- [ ] `R1-04.2` แสดงการ์ด Study Room หนึ่งใบใน Common rooms พร้อมปุ่ม Walk in และสถานะกำลังเชื่อมต่อ แสดงข้อความ “No open rooms yet.” ใน Open rooms
- [ ] `R1-04.3` พาผู้ที่ยังไม่ได้เข้าสู่ระบบไปหน้า Sign in และผู้ที่ยังไม่มีตัวละครไปหน้า Create Character
- [ ] `R1-04.4` ให้ API ตรวจ session และ avatar ก่อนออกตั๋ว และให้ Colyseus ตรวจตั๋วกับความจุตอนเชื่อมต่อ
- [ ] `R1-04.5` แสดงข้อความแยกกรณีห้องเต็มและเชื่อมต่อไม่ได้ พร้อมให้ลอง Join ใหม่

**เกณฑ์ตรวจรับ**

- Discover แสดง Study Room เพียงหนึ่งการ์ดใน Common rooms และ Open rooms แสดงข้อความสถานะว่าง ผู้ใช้สองเครื่องที่กด Walk in พบกันในห้องเดียวกัน
- ผู้ที่ไม่มี session หรือยังไม่มีตัวละครต้องทำขั้นตอนนั้นก่อนเข้าห้อง
- เมื่อห้องเต็มหรือเชื่อมต่อล้มเหลว ผู้ใช้อยู่ที่ Discover และเริ่ม Join ใหม่ได้

## R1-05 เดินและเห็นผู้เล่นคนอื่นแบบ Real-time

ในฐานะผู้เล่น ฉันต้องการเดินในห้องและเห็นเพื่อนเคลื่อนไหว เพื่อเดินเข้าไปหาคนที่อยากคุยด้วย

**งานย่อย**

- [ ] `R1-05.1` เชื่อมปุ่มเดินบนคีย์บอร์ดกับตัวละครของผู้เล่น
- [ ] `R1-05.2` รับตำแหน่งที่คลิกบนพื้นและพาตัวละครเดินอ้อมสิ่งกีดขวางไปยังจุดหมาย
- [ ] `R1-05.3` ให้เซิร์ฟเวอร์ตรวจการเคลื่อนที่เทียบกับขอบฉากและสิ่งกีดขวาง
- [ ] `R1-05.4` ส่งสถานะตำแหน่งและการหยุดเดินให้ผู้เล่นคนอื่นในห้อง
- [ ] `R1-05.5` แสดงชื่อ รูปลักษณ์ และการเคลื่อนไหวของเพื่อนตามสถานะที่ได้รับ
- [ ] `R1-05.6` โหลดรายชื่อและตำแหน่งของผู้เล่นที่อยู่ก่อนให้กับคนที่เข้าทีหลัง
- [ ] `R1-05.7` ทดลองจากสองเครื่องว่าเห็นกันขณะเดินและหยุด และเดินทะลุสิ่งกีดขวางไม่ได้

**เกณฑ์ตรวจรับ**

- ผู้เล่นควบคุมการเดินด้วยคีย์บอร์ด และคลิกพื้นเพื่อเดินไปยังจุดหมายในฉากได้
- เมื่อผู้เล่นหนึ่งคนเดินหรือหยุด ผู้เล่นคนอื่นในห้องเห็นตำแหน่งและการเคลื่อนที่อัปเดตโดยไม่รีเฟรชหน้า
- เซิร์ฟเวอร์ตรวจการเคลื่อนที่ ตัวละครเดินผ่านผนัง เฟอร์นิเจอร์ที่กั้นทาง หรือขอบแผนที่ไม่ได้
- ผู้ที่เข้าทีหลังเห็นตัวละครและตำแหน่งของผู้ที่อยู่ในห้องแล้ว

## R1-06 คุยด้วยเสียงตามระยะและควบคุมไมค์

ในฐานะผู้เล่น ฉันต้องการได้ยินคนที่อยู่ใกล้และควบคุมไมค์ได้ เพื่อเลือกวงสนทนาด้วยการเดิน

**งานย่อย**

- [ ] `R1-06.1` เชื่อมระบบเสียงเข้ากับห้องทดสอบและบัญชีที่ผ่านการตรวจสิทธิ์
- [ ] `R1-06.2` ทำปุ่มเปิดและปิดไมค์ โดยเริ่มต้นสถานะปิด
- [ ] `R1-06.3` แสดงสถานะ Mic off, Mic on และ Voice unavailable ใน Room HUD
- [ ] `R1-06.4` คำนวณระยะระหว่างผู้ฟังกับผู้พูดจากตำแหน่งล่าสุดในห้อง
- [ ] `R1-06.5` ปรับระดับเสียงตามระยะและหยุดเสียงเมื่ออยู่นอกระยะ
- [ ] `R1-06.6` แสดงวิธีแก้เมื่อเบราว์เซอร์ปฏิเสธไมค์ พร้อมให้ผู้เล่นอยู่ในห้องและเดินต่อได้
- [ ] `R1-06.7` นัดทดสอบสองวงสนทนาในห้องเดียวกัน แล้วเดินย้ายวงเพื่อตรวจว่าเสียงเปลี่ยนตามตำแหน่ง

**เกณฑ์ตรวจรับ**

- ไมค์ปิดเมื่อเข้าห้อง ผู้ใช้เปิดและปิดไมค์เองได้ และเห็นสถานะไมค์ปัจจุบันได้
- ผู้เล่นได้ยินเสียงเมื่อเดินเข้าใกล้ผู้พูด เสียงเบาลงเมื่อเดินห่าง และหยุดเมื่อพ้นระยะที่กำหนด
- เมื่อแบ่งผู้ทดสอบเป็นสองวงที่อยู่ห่างกัน คนในแต่ละวงคุยกันได้ตามระยะภายในห้องเดียวกัน
- หากเบราว์เซอร์ไม่ได้รับสิทธิ์ใช้ไมค์ ผู้ใช้เห็นวิธีเปิดสิทธิ์ และยังเดินในห้องได้

## R1-08 ออกจากห้องและกลับเข้าเมื่อการเชื่อมต่อหลุด

ในฐานะผู้เล่น ฉันต้องการออกหรือกลับเข้าห้องได้ เพื่อให้เพื่อนเห็นสถานะของฉันถูกต้อง

**งานย่อย**

- [ ] `R1-08.1` ทำปุ่ม Leave ให้กลับ Discover โดยคงสถานะเข้าสู่ระบบ
- [ ] `R1-08.2` ตัดการรับส่งเสียงของผู้เล่นเมื่อออกจากห้อง
- [ ] `R1-08.3` แจ้งผู้เล่นคนอื่นเมื่อมีคนออก และลบตัวละครของคนนั้นออกจากฉาก
- [ ] `R1-08.4` แสดงสถานะการเชื่อมต่อหลุดและปุ่มลองใหม่
- [ ] `R1-08.5` โหลดสถานะห้องล่าสุดเมื่อกลับเข้ามาและจัดการให้เหลือตัวละครเดียวต่อบัญชีหลังเชื่อมต่อ
- [ ] `R1-08.6` ทดลองกด Leave ปิดแท็บ และตัดเครือข่ายชั่วคราว แล้วตรวจการกลับเข้าห้อง

**เกณฑ์ตรวจรับ**

- เมื่อกด Leave ตัวละครหายจากหน้าจอคนอื่น การรับส่งเสียงของผู้ที่ออกหยุด และยังใช้บัญชีเดิมกด Join จาก Discover เพื่อกลับเข้าห้องได้
- หากการเชื่อมต่อหลุด ระบบแจ้งสถานะและให้ลองเชื่อมใหม่ได้
- เมื่อกลับเข้าห้อง ผู้เล่นเห็นสถานะล่าสุด และคนอื่นเห็นตัวละครของบัญชีนั้นเพียงตัวเดียวหลังเชื่อมต่อสำเร็จ

## R1-11 วัดผล ทดสอบโหลด และซ้อมกู้ระบบใน local

ในฐานะทีมพัฒนา ฉันต้องการเห็นอาการก่อน deploy เพื่อกำหนดขนาด playtest และรู้วิธีกู้ระบบเมื่อบริการล่ม

**งานย่อย**

- [ ] `R1-11.1` รันทั้ง stack ด้วย Compose และใช้ Prometheus, Grafana, Loki กับ Alertmanager ตรวจ API, Join, เสียง และเครื่องที่รันบริการ
